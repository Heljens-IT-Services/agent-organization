# WorkItem Accounting

Backend adoption design for #50/#51/#24. All seven files in this directory form one patch set under `scripts/accounting/`. Existing store/schema/ledger remain authoritative. No starter, delegation, role or organization changes are part of adoption.

`Import-RolloutTaskUsage.ps1` retains the existing completed-turn snapshot reader. Native thread+turn identifies a measurement; task IDs are assignments and all proven aliases are retained by the reader. Cumulative turn snapshots contribute their final accumulated delta once, not a sum of snapshots; the session fallback requires a proven baseline and final snapshot. Missing baseline produces an explicit unknown measurement. Cache and reasoning remain subsets. Existing records are never upgraded from unknown/provisional to final by replacement: contradictory reimports fail and retain all existing data. Same canonical identity, binding, measurement and finality are idempotent.

Bound imports require a reservation/transfer/current artifact and consistent WorkItem, execution, store, task, parent task, thread and available parent native identities. Initial reservation/transfer turn remains expected; further completed turns with the same consistent execution/thread are allowed. The bound initial turn retains `<task>.usage.json`, matching the #18 consumer on develop after PR93/94. Additional turns use `<task>.<thread>.<turn>.usage.json`; importing a later turn first does not occupy the legacy initial path. Native fields serialize in existing D format, local task IDs in N format, store paths retain full original path spelling. Comparisons use canonical GUIDs and Windows store paths. The importer lock serializes cooperating importers; other writers use their own locks, so no global ledger transaction is claimed.

`Get-TaskTokenUsage.ps1` uses one selected record set for totals, missing task coverage, own and diagnostics. Bound filters select only explicitly bound same-store WorkItems/executions; unbound CLI descendants cannot widen this selection. Aliases resolve before selection and each native turn contributes once. Multiple turns of one task are valid. Missing final measurements and provisional records independently keep total unknown while preserving known partials. `AccountingEvidence.psm1` provides the shared normalization, identity/finality/type/range/overflow protection, native deduplication and complete execution correlation, including usage-only evidence.

`Get-WorkItemMetrics.ps1` selects the canonical WorkItem subtree and same-store explicit executions. Root own and tree inclusive coverage are independent. An item with no observed execution expectation gates the tree total; a measured child cannot stand in for an unknown root, and vice versa. Expected initial turns must be present; later turns cannot replace them. Binding conflicts, expected missing turns/executions, provisional/unknown measurements and missing parent metadata are reported separately. Direct explicit WorkItem bindings allow known own measurements despite missing parent registration. All sums use deduplicated own measured values, never inclusive child sums or coordinator goal meters. Observed coverage does not prove complete execution history. Store revision is fixed; sequential ledger and binding reads are not an atomic snapshot.

`Read-ObservedAccountingFamily` adapts explicitly supplied starter artifacts, native rollout JSONL, and native event JSONL. Completed turns with `turn_context` identity and `token_usage_record.turn_token_usage` inside matching `task_started`/`task_complete` ordinals feed the in-memory final-measurement projection; starter job/active bindings may supply the task identity before that projection. Event-log `thread/tokenUsage/updated` values remain provisional thread-total observations without a proven turn baseline and never become final turn measurements. Projection is keyed by thread/turn, replaces an older provisional ledger value in reader memory, retains source paths, and never writes ledger files. Binding or final-measurement disagreements are surfaced and excluded from known sums. The readers accept `ExpectedJobArtifacts`, `NativeRolloutPaths`, and `NativeEventLogPaths`; this explicit source input does not imply an automatic producer caller. The adapter always returns `familyComplete=false`: observed artifacts and completed rollouts cannot prove no unobserved dispatch or future producer turn exists, so it cannot unlock numeric `inclusive`.

Producer handoff required before family inclusive can be numeric: the starter/admission producer must pass the exact root family’s job artifacts and all native rollout paths to the reader, plus an authoritative closure record from the producer that enumerates start intents, reservations, dispatches and native turns through a bound final sequence/epoch for that root. The closure must identify its source records, root/scope and sequencing semantics and be independently readable; a boolean, manifest authored by the accounting consumer, result completion, or file hash alone is insufficient. Until then reports retain observed known partials, concrete missing observations and an explicit unknown inclusive value. The current starter call sites do not yet supply these new source parameters.

`Set-WorkItemGoalMeasurement.ps1` appends `workitem-goal-measurement/v1:` JSON strings to existing `result.evidence` through the existing revision/lock store path. Required fields: integer `version=1`, exact `workItemId`, `measurementId`, `metric`, `target`, `unit`, nonempty string `value`, explicit UTC `measuredAt`, `source`, `definition`, `period`. The setter requires exact current `goal.metric`, retains goal target and canonical status, and rejects terminal items or conflicting existing IDs. The reader permanently excludes every contradictory measurement ID before resolving any goal decision; an A/B/A sequence never revives the ID. Property ordering is not a conflict.

`WorkItemMetricEvidence.psm1` projects existing stored actor reviewer objects and single string criterion evidence. Current implementation criteria IDs/descriptions and goal come from the fixed store snapshot. Integrated #18 current.startingSnapshot and transfer.candidate are read as full same-store, same-WorkItem version snapshots with their artifact path/field as source; sourceResult alone never supplies historical criteria. Conflicting executions cannot supply historical snapshots. When these sources are absent, prior versions need source-bound `workitem-version-evidence/v1:` strings in existing result evidence: integer `version=1`, exact `workItemId`, UTC `implementedAt`, nonempty `source`, complete `criteria` array of `{id,description}`, and that version's `goal` containing `description`, `metric`, `target`. Conflicting snapshots permanently exclude that version from complete-review/goal projections. Raw historical individual decisions remain visible with their completeness limits.

Each complete review requires exact version criteria membership, one boolean result and nonempty string evidence per criterion, canonical reviewer actor, UTC checkedAt >= implementedAt and verification.passed matching the AND of criterion results. Current criteria are never silently reused for older implementations. Complete decisions are ordered by checkedAt; conflicting decisions for the same implementation/review timestamp cannot be projected.

Fachbasis defines first acceptance as acceptance on the first proven review attempt in the same reporting context. An earliest observed decision alone does not prove it was first. Optional `workitem-review-history/v1:` evidence binds integer `version=1`, exact `workItemId`, `source`, `firstCheckedAt`, `firstDecisionSource` to the proven first complete review. Contradictory earlier stored attempts, incomplete first review or conflicting history claims keep `firstAcceptance=null`. This does not require proving that the first review concerned the first implementation version. The report returns a separate firstObservedDecision and a classified subtree rate with numerator, denominator and unknown count; absent denominator yields unknown. Explicit complete history additionally requires boolean `historyComplete=true`, UTC `coveredThrough`, `decisionKeys` (normalized implementation UTC + '/' + review UTC) and `implementedVersions` arrays exactly matching all observed versions and complete decisions, with no conflicting/missing review completeness. Claims remain source bindings, not independently fetched source verification.

An evidenced later version B after a complete failed decision A contributes once to `evidencedReworkAttemptLowerBound`, even if older history is missing. Another review of A is not a new implementation. The source of B and latest preceding failed decision are returned. Failed review count, failed version lower bound, criterion failure finding lower bound, and completed correction/review cycle lower bound remain separate. Completed cycles additionally require a complete review of B. Exact rework attempt count is exposed only with the explicit full-history manifest; otherwise null. A zero lower bound means no such event evidenced, not no rework occurred. Free-text evidence may contain more individual defects than one criterion failure; the criterion count is a lower bound, not a parsed defect inventory.

`workitem-goal-decision/v1:` is an Accounting evidence envelope in the existing single-string `verification.results[].evidence`, not a schema or role contract. It requires integer `version=1`, exact `workItemId`, UTC `implementedAt`, matching `criterionId`, version-bound `goal.metric/target`, parallel nonempty `measurementIds` and `measurementSources` arrays with unique measurement IDs, `unit`, `definition`, `period`, `sourceReview`, `rationale`, and `assessment` (`achieved` with criterion.passed=true or `not_achieved` with false). Every referenced measurement must match goal, source, unit, definition and period and precede checkedAt. Reviewer and checkedAt come from the surrounding complete verification, never from a second invented reviewer identity. Missing `scope` or `scope=criterion` produces only an individual goal claim. Overall projection requires explicit `scope=whole_goal` plus `goalDefinitionSource` and `validityContext`, expressly declaring the reviewer's overall goal interpretation. Only current-version whole-goal decisions affect current lifecycle/root achievement; conflicting assessments keep it unknown. No inferred aggregation of partial criteria and no automatic free-text target/value comparison are implemented. Leads, activities and customer outcomes remain different metrics.

All evidence formats above are accounting-only design conventions inside existing evidence strings. Existing free text is preserved, shown as raw unresolved evidence and never rewritten into a reviewer decision. Absent actual historical/first-review/goal sources remain specific unknowns; no fabricated evidence is necessary to adopt the code. Read-back and diff evidence for this design are not runtime, independent-review or parent-acceptance evidence. No tests, parsers, validators, production functions or demonstrations were run for this delivery. No CI activation.
